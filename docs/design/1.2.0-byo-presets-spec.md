# VoLum 1.2.0 — BYO + Presets: UX + data model + backend contract

Status: **authoritative** for 1.2.0. Supersedes `1.2.0-ia-convergence.md` (frozen)
and the `volum-1.2.0-ia-directions.canvas.tsx` Canvas. This is the refined "D8"
design as actually built in the C++ UI shells on `feature/1.2.0`.

The UI-shell phase is **pure UI on an in-memory mock** (`VoLumCustomContentMock.h`):
layout, navigation, and the live (speaker × channel) snap/coverage are real; all
disk IO, serialization, DSP routing, and content import/manage are stubs. This
doc is the contract the backend session implements against.

---

## 1. Scope

Four features, shipping together:

- **F5 Presets** — per-amp named snapshots, switchable live from the AMP header.
- **F6 Bring-your-own amp** — free-form, file-first custom amps as real sidebar
  entries.
- **F7 Bring-your-own IR** — custom IR cabs chosen from the speaker row, sourced
  from the amp's DIRECT capture.
- **F8 Import your own pedals** — imported PRE captures, managed inline in the
  PRE capture dropdown.

There is **no unified "Custom" overlay / library hub**. Import and management of
IRs and pedals live inline in the controls that select them. The only standalone
dialog is the custom-amp builder.

## 2. UX behavior (as built)

### 2.1 F5 — Per-amp presets (AMP header)

- A preset bar sits top-left of the main panel: `‹  PRESET / <name>  ▾  ›`.
- A **preset is a named full snapshot of one amp's `VoLumAmpSettings`** — its
  speaker/cab selection (including a custom-IR cab choice), channel, AMP knobs,
  PRE pedal selections/params, POST FX, and dual-amp config. It is NOT a global
  cross-amp rig.
- Each factory or custom amp owns its **own** preset bank. Switching amps swaps
  the bar to that amp's bank.
- Today's continuously auto-saved per-amp state remains as the **unsaved
  "live/last-used" state** (`(unsaved)` label when no named preset is active).
- `‹` / `›` cycle the current amp's presets in place (footswitch-mappable),
  without opening any overlay. They are inert (dimmed) when the amp has no
  presets.
- The header bar reads **`No Preset`** when nothing is recalled, the preset name
  when one is active, and appends **`(unsaved)`** when the live rig diverges from
  the recalled preset (any cab/channel/AMP/PRE/POST/IR change marks it dirty).
- The `▾` / name opens the **preset dropdown** (the shared scrollable list-menu):
  a pinned **`Default (factory settings)`** row at the top (with a divider) that
  resets the amp's cab/channel/AMP/PRE/POST params to shipped defaults and sets
  the bar back to `No Preset`; then the amp's presets (click = recall); then
  `Manage presets…`.
- All dropdowns/overlays share dismissal UX: click-outside closes, `Esc` closes
  the active overlay/dropdown.
- Global cross-amp preset banks are explicitly **out of scope** for 1.2.0.

### 2.2 F6 — Custom amps (sidebar + builder)

- Custom amps render as **real list entries** in the sidebar, in a labeled
  `CUSTOM` section **below** the 15 factory amps. The list scrolls when custom
  entries overflow; the factory block plus an (always-present) section header fit
  without a scrollbar.
- Empty state: the section header is a single `+ CUSTOM` affordance (click =
  add). Populated state: a `CUSTOM` label with a `+` button on the right, then
  one row per custom amp. Each row shows a diamond marker, the name, and — on
  hover/selection — **pen (edit)** and **bin (delete)** affordances.
- Selecting a custom amp drives the rig (mock: updates hero + name; backend:
  loads the manifest).
- Selecting a custom amp also makes the **cabinet row + channel stepper
  custom-aware**: the cab buttons show that amp's own named cabs (`DIRECT`/No Cab
  plus its cab-slot names), cab slots with no capture render disabled (`--`), the
  Custom IR clears, and the channel stepper follows the focused cab. Switching
  back to a factory amp restores the stock `G12/G65/V30` row. Custom amps have no
  dual/stereo affordance in 1.2.0 and do **not** appear as a factory support amp
  (they do appear under the support picker's CUSTOM group — see §2.5).
- **Builder** (the only standalone dialog) is **file-first** with a fixed cab
  structure (one DIRECT + three renameable cab slots, mirroring the three stock
  cabs):
  - Profile name field; a **fractal-art picker** (3×2, six procedural styles, no
    captions) for the amp's thumbnail/hero art.
  - `+ Add .nam files…` — add any number of captures.
  - Per file: a **slot** chip (DIRECT or one of the three cabs) and a **Channel**
    chip (Ch 1–8). The matrix is **sparse**.
  - Live **coverage** grid: four fixed rows (DIRECT + 3 cabs); the three cab
    labels are **inline-editable input chips** (pen glyph) wired to a 3-char,
    uppercased rename (`NormalizeCabName`); columns grow from a baseline of 4 to
    the highest assigned channel, hard-capped at 8.
  - **Validation**: colliding files (same slot+channel) get a red row tint/border
    and the shared coverage cell gets a red `x2` badge. `Save` is disabled — with
    the button text stating why — on no files, any unassigned file, or any
    duplicate (`SaveDisabledReason`).
  - Editing an amp reopens the same builder on its manifest. No destructive file
    renaming — the mapping is a manifest, files keep their names.

### 2.3 F7 — Custom IR cabs (speaker row)

- The cabinet row is a **single row, no section captions**:
  `No Cab | <cab1> <cab2> <cab3> | Custom IR`. Index 0 is **No Cab** (the old
  "AMP"/DIRECT button, renamed so users stop hitting it by accident); the three
  cab buttons are the stock or custom cab names; the last segment is **`Custom
  IR`** (capitalized) with a small impulse glyph, showing the chosen IR name when
  active.
- Clicking `Custom IR` opens an anchored dropdown (shared list-menu): the global
  IR library, then `Manage custom IRs…`. There is no "use baked cab" row —
  selecting any cab (or No Cab) clears the custom IR.
- Selecting an IR makes it the **active cab**: the baked-cab buttons read as
  unselected and the button shows the IR name. Conceptually the amp's **DIRECT
  capture for the current channel is run through the chosen IR convolver**,
  covering all of that amp's channels.
- IR files are a **global library**; the *active IR-as-cab choice is per-amp
  state* and is captured by presets.

### 2.4 F8 — Imported pedals (PRE capture dropdown)

- The PRE capture dropdown (PRE-NAM slots) gains, after the factory captures, a
  `CUSTOM` group header, the imported captures, then a `Manage custom pedals…`
  action row. Imported captures sit under CUSTOM (no per-row "imported" badge).
- Import happens from the Manage panel via a file dialog (`.nam`); no separate
  pedal library hub.

### 2.5 Dual Amp — custom support partner

- The Dual Amp **support picker** is the shared scrollable list-menu: `(none)`,
  the 15 factory amps, then a `CUSTOM` group (shown only when ≥1 custom amp
  exists).
- Picking a custom support amp renders its **fractal art + name** in the SUPPORT
  hero lane; focusing that lane shows its **custom cabs + channels** (the shared
  cabinet row / channel stepper retarget to the focused lane). The preset still
  belongs to the main amp but may include a custom support reference.
- Display + session only in the 1.2.0 shell; the persistence shape (a support
  reference by id) is in §3.5.

### 2.6 Manage panels (presets / IR / pedals)

All three Manage screens share one compact layout: a single top action button
(**Save current as new** for presets, **Import…** for IR/pedals), a scrollable
list, and **inline per-row icons** — presets show overwrite/rename/delete, IR and
pedals show rename/delete. Deletes route through a shared **"Are you sure?"**
confirm modal. **Double-clicking a row** performs its primary action and closes
(recall preset / use IR on the focused cab / load pedal into its PRE slot). The
builder keeps its larger two-pane dialog; Manage uses a smaller dedicated panel.

## 3. Data model

### 3.1 Custom-amp manifest (F6) — production logic, doctested

Defined in `VoLumCustomContentMock.h` (`volum::custom`); these types/helpers are
the intended production shapes. A custom amp has **exactly one fixed DIRECT slot
plus three renameable cab slots** (mirrors the three stock cabs), and files
reference a slot by index rather than a free-form speaker string:

```cpp
constexpr int kDirectSlot     = -1;   // amp-only / no cab
constexpr int kUnassignedSlot = -2;   // file not yet placed
constexpr int kNumCabSlots    = 3;    // renameable cab slots (0..2)
constexpr int kMaxChannels    = 8;    // hard cap on gain stages
constexpr int kNumCustomArts  = 6;    // procedural fractal styles

struct CustomNamFile {
  std::string file;     // display filename (manifest stores the stored path)
  int slot = kUnassignedSlot;  // kDirectSlot, 0..kNumCabSlots-1, or kUnassignedSlot
  int channel = 0;      // gain stage 1..kMaxChannels; 0 = unassigned
};

struct CustomAmp {
  std::string id;       // stable opaque id (see §3.5) — NOT the name/index
  std::string name;
  int art = 0;          // 0..kNumCustomArts-1
  std::array<std::string, kNumCabSlots> cabNames = {"CB1","CB2","CB3"}; // <=3 chars, UPPER
  std::vector<CustomNamFile> files; // sparse; DIRECT + up to 3 cabs x up to 8 ch
};
```

Pure helpers (covered by `test_volum_custom_content.cpp`):

- `IsDirectSlot(slot)` / `SlotAssigned(slot)` — DIRECT vs a real placement.
- `SlotLabel(amp, slot)` — `"DIRECT"` or the cab slot's (renamed) name.
- `NormalizeCabName(in)` — uppercases, strips spaces, caps at 3 chars (drives the
  inline cab-name chips; empty result is rejected so a slot keeps its prior name).
- `FileAssigned(file)` — has a real slot and `channel >= 1`.
- `UnassignedCount(amp)` — files still needing assignment.
- `AmpSlots(amp)` — populated slots, DIRECT first then cab slots in order.
- `AmpSlotChannels(amp, slot)` — sorted unique channels for a slot.
- `CellFileCount(amp, slot, channel)` / `FileIsDuplicate(amp, i)` /
  `HasDuplicate(amp)` — (slot,channel) collision detection for validation.
- `MaxAssignedChannel(amp)` — highest channel in use (drives coverage columns).
- `SaveDisabledReason(amp)` — empty when saveable, else the human reason the
  builder Save button shows: no files / an unassigned file / a duplicate
  (slot,channel). Save is enabled **iff** this is empty.

**Backend manifest schema (suggested):** one JSON manifest per custom amp under
user content, addressed by stable `id`, e.g.

```json
{
  "schemaVersion": 2,
  "id": "amp_9f3c1a",
  "name": "My Plexi A/B",
  "art": 2,
  "cabNames": ["G65", "V30", "CB3"],
  "files": [
    { "path": "captures/AMP-Plexi-direct-1.nam", "slot": -1, "channel": 1 },
    { "path": "captures/G65-Plexi-Ch1.nam",      "slot": 0,  "channel": 1 }
  ]
}
```

Files are referenced by stored path; import copies the user's `.nam` into user
content (no rename). `slot` is `-1` for DIRECT or `0..2` for a cab slot whose
display name lives in `cabNames`. The factory
`{SpeakerPrefix}-{AmpCode}-{Channel}.nam` filename convention does **not** apply
to custom amps — the manifest is the source of truth.

### 3.2 Custom-IR-as-cab (F7) routing

Signal path for an active custom IR cab:

```
DIRECT amp capture (per channel) → tone stack → selected custom IR convolver → POST
```

Reuses the existing global IR convolver slot (`mIR`, post-tone-stack in
`VoLumProcessBlock.inc.cpp`). In 1.2.0 it is driven by the **per-amp speaker
selection** (a custom-IR cab choice) instead of only the bare `kIRToggle`. When a
baked cab is selected, the convolver is bypassed as today. IR files live in a
global library; the active selection is per-amp and travels in presets. The
support/dual lane keeps its current (no per-lane custom IR) behavior unless the
backend extends it.

### 3.3 Presets (F5)

A preset = `{ name, VoLumAmpSettings copy }`, keyed under the owning amp
(factory amp index or custom-amp id). The live/last-used state is the existing
auto-saved `mVolumAmpSettings[ampIdx]`; Save copies it into a named slot, Recall
copies a named slot back over it. `VoLumAmpSettings` must already capture the new
custom-IR-as-cab choice for presets to round-trip it.

### 3.4 Global libraries

- IR library: list of imported IRs (stable id + display name + stored path).
- Pedal-capture library: imported PRE captures (stable id + label + group +
  stored path). For DAW project chunk back-compat they also keep **stable
  legacy indices** in the PRE capture index space (so existing chunks resolve).

### 3.5 Stable IDs + settings JSON schema (backend)

**Reference everything custom by a stable opaque id, never by name or list
position.** Names are user-editable and positions shift on add/remove, so any
cross-reference (a preset pointing at a custom IR, a support-amp slot pointing at
a custom amp, a PRE slot pointing at an imported pedal) MUST store the id.

- Id shape: short opaque string, e.g. `amp_<rand>`, `ir_<rand>`, `pedal_<rand>`,
  `preset_<rand>`. Generated once at create/import; never reused after delete.
- Display order is a separate concern (a `order` array or natural insert order);
  reordering never changes ids.

`volum-settings.json` gains **additive, optional** keys (older builds ignore
unknown keys; this build tolerates their absence). Bump a top-level
`schemaVersion` (was implicit `1`; custom content is `2`):

```json
{
  "schemaVersion": 2,
  "customAmps":   [ { "id": "amp_9f3c1a", "manifest": "amps/amp_9f3c1a.json", "order": 0 } ],
  "irLibrary":    [ { "id": "ir_22b0",  "name": "Mesa 4x12 sm57", "path": "ir/ir_22b0.wav" } ],
  "customPedals": [ { "id": "pedal_7e1", "name": "Klon",  "group": "drive", "path": "pedals/pedal_7e1.nam", "legacyIndex": 32 } ],
  "presetBanks": {
    "factory:7":     [ { "id": "preset_a1", "name": "Church clean", "settings": { /* VoLumAmpSettings */ } } ],
    "amp_9f3c1a":    [ { "id": "preset_b2", "name": "Lead",         "settings": { /* ... */ } } ]
  },
  "perAmp": {
    "factory:7":  { "activeIrId": "ir_22b0" },
    "amp_9f3c1a": { "supportRef": { "kind": "custom", "id": "amp_4d20" } }
  }
}
```

- Preset banks are keyed by owning amp id (`factory:<index>` for the 15 stock
  amps, the opaque id for custom amps).
- A support-amp reference is `{ kind: "factory", index }` or
  `{ kind: "custom", id }`; "(none)" is the absence of the key. (In the 1.2.0
  shell the custom support partner is display + session only; this is the
  persistence shape the backend writes.)

### 3.6 Tolerant reader + corruption policy (backend)

The settings reader MUST be **lenient and never destructive**:

- Ignore unknown keys (forward-compat with newer builds).
- Clamp out-of-range scalars to valid ranges; skip individual entries that are
  malformed (bad type, missing required field) rather than aborting the load.
- Drop **orphaned references** (a ref whose target id no longer exists) using the
  per-type fallbacks in the removal matrix below — never wipe the file.
- If the whole file is unparseable (not valid JSON / wrong root shape): rename it
  to `volum-settings.json.bak` (overwriting any previous `.bak`) and start from
  defaults, so the user can recover manually and we never silently lose data.
- Writes are atomic: write to a temp file and rename over the live file.

### 3.7 Removal matrix (what each delete does to references)

| Removed | Effect on references |
| --- | --- |
| Custom **pedal** | Every PRE NAM slot referencing it defaults to **no pedal** (EMPTY). |
| Custom **IR** | Each amp whose active cab was that IR falls back to the **first available cab/channel in that amp's coverage** (for sparse custom coverage: first populated cab slot, else DIRECT). Never leaves a dangling IR cab. |
| Factory **support** amp | n/a (factory amps are not removable). |
| Custom **support** amp | Any support reference pointing at it resets to **"(none)"** (support lane empty); Dual Amp stays in its current on/off state. |
| Active **MAIN** custom amp | Selection falls back to a **factory amp**; that custom amp's preset bank is **cascade-deleted** with it. |
| **Preset** | Just removed from its bank. A shared/foreign reference to a missing preset id is dropped (bar reads "No Preset"). |

Orphaned references (e.g. a recalled preset that points at since-deleted custom
content) are resolved with the above per-type fallbacks at read time — the file
is corrected in place on next save, never discarded.

## 4. Backend contract (what the next session must implement)

Everything below is **stubbed** in the shells:

1. **Storage layout** under user content (sibling of `volum-settings.json`):
   custom-amp manifests + copied `.nam`; IR library + copied IR wavs; imported
   pedal captures. Define paths and an index/registry file.
2. **Manifest IO** — create/read/update/delete; import copies files in; builder
   Save writes the manifest; edit loads it. Delete removes registry entry
   (and optionally orphaned files).
3. **Persistence / serialization**
   - `volum-settings.json`: additive optional keys only, all custom content
     addressed by **stable opaque ids** (§3.5); bump `schemaVersion` to 2. Use
     the **tolerant reader + `.bak`-on-corruption** policy (§3.6) and apply the
     **removal matrix** (§3.7) for orphaned references. Must stay
     backward/forward compatible.
   - DAW project chunk: **append-only tail sections** for preset banks + per-amp
     custom-IR-cab + custom-amp binding + custom support-amp ref (all by id).
     Bump chunk version with a version-branch test
     (`test_volum_chunk_version.cpp`) and round-trip/bounds coverage
     (`test_volum_chunk_codec.cpp`).
   - A portable **import/export** of settings + custom content is tracked
     separately in `backlog/F10-settings-import-export.md` (out of scope here).
4. **DSP wiring**
   - Route the active custom-IR-as-cab through `mIR` from the DIRECT capture for
     the current channel (§3.2); update `VoLumProcessingPlan.h` enablement and
     add a `test_volum_processing_plan.cpp` case.
   - Load custom-amp `.nam` per (slot, channel) from the manifest; wire channel
     discovery to `AmpSlotChannels`.
   - Couple custom amps into amp selection alongside `kAmps`/`kAmpCount`
     (custom-amp ids vs factory indices), as MAIN and as a dual SUPPORT partner.
5. **Import/Manage flows** — IR import + rename/delete (speaker-row dropdown),
   pedal import (label + group) + rename/delete (PRE menu). Keep PRE capture
   indices stable.
6. **Presets** — wire Save/Save-As/Rename/Delete/Recall + `‹`/`›` cycle to the
   per-amp bank; ensure Recall reapplies the full `VoLumAmpSettings` incl. the
   IR-cab choice; expose footswitch/MIDI mapping for prev/next.

Add doctests for every confirmed behavior (manifest IO, routing decisions,
chunk round-trip), per the VoLum workflow rule.
