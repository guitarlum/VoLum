# VoLum 1.2.0 — Thermo-Nuclear Code-Quality & Performance Review

Branch: `feature/1.2.0` (PR #19 -> `dev`). Review date: 2026-06-21.

Scope: the full 1.2.0 delta vs `dev` — the BYO/presets backend (content store +
bridge), the custom-content UI, the signal-chain/serialization changes in
`NeuralAmpModeler.cpp`, plus a performance pass focused on the standalone
corner-grip resize and real-time (audio-thread) safety.

This document is the prioritized findings record. Items are tagged:

- **LANDED** — fixed on this branch in this pass (low-risk, test-covered).
- **BACKLOG** — filed as a ready-to-implement ticket (bigger / behavior-risky).
- **NOTE** — observation, no action required now.

Severity: P0 (correctness/RT), P1 (structure/maintainability), P2 (polish).

## 0. Headline: standalone resize stutter + "detach" — LANDED

**Symptom:** dragging the bottom-right corner grip stuttered and could briefly
leave a dark gap where the resized native window outran the redraw (UI looked
"detached" from the frame).

**Root cause (confirmed):** a corner-resizer drag (`EUIResizerMode::Scale`)
called `IGraphics::Resize` *synchronously on every `WM_MOUSEMOVE`*. Each call
resized the native window (`SetWindowPos` x2) and ran a full GL `DrawResize`.
Mouse-moves arrive faster than vblank, so several full window-resize + repaint
cycles ran per frame (stutter), and the DWM showed the resized frame before the
lagging GL redraw filled it (the dark gap). Steady-state rendering at 1758x1220
held 60 fps / 16.5 ms, proving the cost was the *per-move resize storm*, not raw
fill rate.

**Fix (iPlug2 mirror `5c1ae1987`):** `OnDragResize` now records the latest drag
target; `IsDirty()` flushes a single `Resize` per frame via `FlushDragResize()`;
`EndDragResize()` flushes any pending target first. The target depends only on
the mouse-down anchor and the current cursor position (the `x * GetDrawScale()`
term cancels the live draw scale), so the coalesced result is identical to the
old per-move path — only the cadence changes (N resizes/frame -> 1/frame, paced
to the display tick). Verified: grow + shrink both fill cleanly, thumbnails/hero
scale, 60 fps; tests stay green (371 cases).

New tool: `NeuralAmpModeler/scripts/win-drag.ps1` injects a reproducible
corner-grip drag for resize profiling (pairs with `win-screenshot.ps1` and the
`VOLUM_SHOW_FPS=1` overlay).

## 1. Real-time / audio-thread safety

### P0 / NOTE — audio path is free of content-store, JSON, and filesystem
`ProcessBlock` / `VoLumProcessBlock.inc.cpp` do **not** touch
`GlobalContentStore()`, JSON, or `std::filesystem`. Model/IR loading is deferred:
UI/`OnIdle` queues -> loader thread -> a drain stages pointers. Good.

### P0 / BACKLOG (P2-...) — staging drain still takes mutexes on the audio thread
`_ApplyDSPStaging()` (top of every `ProcessBlock`) calls
`_VolumDrainLoaderResults()`, which takes `mVolumLoaderMutex` and `mStagingMutex`
and may call `model->Reset()` (can allocate inside NAM). This is pre-existing
debt that 1.2.0 extends. Move staging commits to a lock-free SPSC queue and
`Reset()` on the loader thread before enqueue. See `P2-volum-1.2.0-rt-and-perf-hardening.md`.

### P0 / BACKLOG (P2-...) — main I/O buffers can resize on the audio thread
`_PrepareBuffers` may `resize` `mInputArray`/`mOutputArray` when `numFrames`
changes mid-stream. Dual-amp scratch already pre-reserves + asserts capacity;
main buffers should do the same (reserve to max block size in `OnReset`, assert
in `ProcessBlock`).

### P1 / BACKLOG — `_VolumSelectIR` does a sync WAV load on the UI callback
Not the audio thread, but a UI hitch; route IR loads through the same async path
as NAM models.

## 2. Correctness bugs

### P0 — `RemoveCustomAmp` deleted by display leaf, orphaning files — LANDED
`RemoveCustomAmp` called `RemoveStoredFile(f.file)`. For amp manifests `file` is
the display leaf ("G65-Plexi.nam"); the resolvable path is `f.storedPath`
("amps/amp_x__G65-Plexi.nam"). Deleting by leaf silently resolved to the wrong
path and orphaned every copied `.nam` on disk. Fixed to use `f.storedPath`
(`VoLumContentStore.h`), plus an on-disk regression test in
`test_volum_content_store.cpp` ("...removes its copied files by storedPath") that
imports a real file, removes the amp, and asserts the file is gone.

### P2 / BACKLOG (Q3-...) — `activePresetId` restore relabels the live scene (niche drift)
Re-verified: restore re-applies the live *saved* scene and relabels the matched
preset (`Unserialization.cpp:682`, `_VolumRestoreSessionSelection`). In the normal
case the knobs are correct (they are the user's saved state). It only diverges for
a **custom** amp whose shared-library scene was changed by another project between
saves — custom scenes are library-global by design and not stored in the DAW
chunk — so the chunk relabels the (now drifted) library scene as the preset.
Applying `pr.settings` on the matched-preset path would harden this. Niche +
behavior-risky; not urgent. (Originally flagged P0 by the audit; downgraded after
reading the restore path.)

### NOTE (not a bug) — `customSupportId` id-tail field is dead, support restores via the scene
Re-verified: `_VolumApplyAmpSettings` resolves the custom support partner from the
scene's `supportCustomId` (`VoLumSettings.inc.cpp:618`), and factory-slot support
restores from `perAmpSupportId`. The id-tail's `customSupportId` (written at
`NeuralAmpModeler.cpp:2153`) is never read but the partner is restored correctly.
The unused field can be dropped as cleanup; no behavior fix needed. (Originally
flagged P0 by the audit; corrected here.)

### P1 / BACKLOG (Q3-...) — `_VolumActiveScene()` inserts empty scenes on read
It returns `customScenes[id]` (`operator[]`), so any *read* path (dirty check,
IR-empty check) with a stale/erased id silently persists a default scene. The
scene is created at selection so it doesn't bite in practice, but it is a latent
footgun. The fix needs a read/write split (mutable accessor keeps insert
semantics; a const "or-default" accessor for reads) — not a one-liner, hence
backlog. Latent, not user-visible.

### P2 / BACKLOG (Q3-...) — pedal legacy-index cap collides at 127
Once `nextPedalIndex > 127`, `AddPedal` clamps every new pedal to 127 ->
colliding PRE-capture indices, no error. `PedalLegacyIndexAt` also returns `0`
(== EMPTY) for out-of-range. Reject the add when the 64-pedal pool is full; use a
sentinel (-1) for OOR.

## 3. Structure / maintainability

### P1 / BACKLOG (Q2-...) — `VoLumCustomUi.h` is 1964 lines, 73% one class
`VoLumCustomOverlayControl` alone is ~1407 lines and owns two full screens
(Manage CRUD + Builder), popups, import, and a per-frame int-encoded hotspot
registry. The file also holds `VoLumPresetBarControl`, `VoLumListMenuControl`,
and `VoLumConfirmDialogControl`. Violates the repo's own ~500-line header
discipline. Phased decomposition (umbrella + per-control headers, then split the
overlay via Manage/Builder helper headers over a context struct) in
`Q2-volum-1.2.0-structure-decompose.md`.

### P1 / BACKLOG (R4-...) — the "Mock" content bridge is half pass-through, mis-named
`VoLumCustomContentMock.h` is a production bridge over `GlobalContentStore()`,
not a mock. ~50% of its ~44 symbols are trivial projections/lookups; ~30% earn
their keep (index<->opaque-id, name dedup on write, preset-owner routing, DI
hooks). The plugin already bypasses it in ~40 sites via `GlobalContentStore().reg()`
directly — two access styles, one backend. Recommendation: **rename + partial
collapse** (rename file/symbols, move preset hooks + `ActivePresetOwnerKey` onto
the plugin instance, delete the projection getters so the UI reads the registry
directly, move mutations into `content::ContentStore`). Full delete is high-risk
(index semantics everywhere) and is the last step. See `R4-...`.

### P1 / BACKLOG (Q2-...) — duplicated UI primitives
- Scrollbar track/thumb math copy-pasted 3x in `VoLumCustomUi.h`; `VoLumAmpList.h`
  already has `DrawScrollbar`. Extract `DrawVoLumScrollbar` into
  `VoLumColorHelpers.h`.
- Pen/bin/overwrite glyphs triplicated with `VoLumAmpList.h`.
- `VoLumPreCaptureMenuControl` (`VoLumTriptychMenus.h`, ~210 lines) duplicates
  `VoLumListMenuControl` despite the shared-control rule; the support picker was
  migrated, the PRE picker was not. Unify onto `VoLumListMenuControl::Row`.

### P1 / NOTE — builder speaker/channel popup is not list-disciplined
Per `volum-ui.mdc`, every growable list must clip to its rect + scroll. The
Manage list, file manifest, and list-menu all comply; the builder's
speaker/channel **popup** (`DrawPopup`) has no clip/scroll/wheel and can draw
past the panel for an 8-row channel picker. Quick compliance fix folded into Q2.

### P2 / BACKLOG (Q2-...) — `ManageKind` branching x10 and int-encoded hotspots
The triple-mode `switch (mManageKind)` is repeated ~10 times; replace with a
`ManageKindTraits` table. The `kRow*Base = 500/600/700` int hotspot namespace is
fragile; structured hit regions would be safer. Dead code: `RowAt()` and
`mTextFileIdx`.

## 4. Performance (non-RT)

### P1 / BACKLOG (P2-...) — dirty-check serializes JSON on every knob move
`AmpSettingsEqual` builds two full JSON trees and string-compares; called from
`_VolumRecomputePresetDirty` on param changes. Use a field-wise / hashed compare.

### P1 / BACKLOG (P2-...) — settings-save churn under automation
Every param change sets `mVolumSettingsDirty`, and `OnIdle` always calls
`_VolumSaveCurrentToSettings()`; with custom scenes redirecting to
`GlobalContentStore`, automation -> per-sample map writes + atomic JSON writes in
standalone. Dirty only VoLum-owned params and coalesce saves.

### P2 / NOTE — projection getters rebuild static vectors on every list read
`MockCustomAmps()` etc. clear + refill a `static` buffer per call with a
"read immediately, never hold" contract that isn't enforced. Goes away with the
R4 collapse.

## 5. Serialization

### NOTE — the chunk id-tail codec is robust and well-tested
`VoLumChunkIdTail.h` bounds-checks offsets/lengths, is sentinel-guarded, parses
JSON leniently (catch-all -> false), and appends after the fixed binary block so
old readers are untouched. Covered by `test_volum_chunk_codec.cpp`. Minor: the
written `schemaVersion` / `kVoLumIdTailSchema` are never validated on read (no
migration hook yet).
