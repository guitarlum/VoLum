# F7 — Bring Your Own IR (cabinet impulse response)

Plan surfacing VoLum's existing-but-hidden impulse-response convolver as a first-class user feature inside the Custom area. VoLum already links the upstream NAM convolver (`AudioDSPTools/dsp/ImpulseResponse.h`, the `kIRToggle` param, `_StageIR` / `_ApplyDSPStaging` in `NeuralAmpModeler.*`), but the IR file browser is currently VST3-only and effectively hidden (see the upstream fence note in `neural-amp-modeler-native.mdc`). A user IR is a separate `.wav` cabinet impulse that sits AFTER the amp in the chain — most useful with a DIRECT / no-cab capture (including a custom amp's DIRECT slot) — and is NOT a cab-baked full-rig capture. Make the IR loader available in BOTH standalone and plugin. Decide: chain placement relative to the speaker/cab model and POST block; the UI affordance (an IR slot/card in the Custom area with load / clear, on-off reusing `kIRToggle`, and optional IR level/mix); storage of user IRs in the F6 user-content area; persistence in settings and in presets (F5 referencing a user IR -> reuse F5's missing-content handling); and DSP confirmation (sample-rate handling/resampling, latency, NaN scrub via `volum::ScrubNonFiniteInPlace`). Produce a feature ticket with: chain/routing decision, UI spec, storage + persistence schema, DSP verification notes, tests (IR load + process finite/bounded, toggle bypass identity per `test_volum_bypass_identity.cpp`, settings/preset round-trip referencing an IR), docs EN/DE + screenshots, changelog. Do not implement.

This ticket depends on F6 (Custom area + user-content storage). Work must happen on a dedicated feature branch off the latest `dev`, named `feature/bring-your-own-ir`. Do not commit to `dev` or `main` directly. The branch is merged back into `dev` only after the ticket's acceptance criteria are met and tests/docs/changelog are in place. Never promote to `main` outside of a release.
