# 1.2.1 pre-release audit — what was fixed and what was deferred

Reference document, not a planning prompt.

Before shipping 1.2.1 the whole VoLum surface was audited line by line by 19
independent review passes (9 with Opus 5, 10 with GPT-5.6), each scoped to one
subsystem. The full reports, with file:line evidence, mechanism, repro and a
proposed regression test per finding, are committed under:

- `audit-notes/opus5/` — 9 reports
- `audit-notes/gpt56/` — 10 reports

This file is the triage ledger over those reports: every finding, its reported
severity, and whether 1.2.1 fixed it. Use the report + finding id to get the
evidence; nothing is re-derived here.

Two policies shaped the triage:

- **Audio voicing was frozen for 1.2.1.** Defects were fair game (gap, click,
  NaN, wrong gain, a control that does not apply). Anything that would move the
  intended tone — filter curves, drive, envelope times, mix laws, effect tuning —
  was reported and left alone. Several deferred items below are *defects* whose
  fix is inaudible; they are deferred for release-risk reasons, not tonal ones.
- **Fix what is provable, defer the rest with evidence.** Everything marked
  DEFERRED has a written mechanism in the audit notes. None of it is a hunch.

## Deferred, with a promoted planning prompt

Three clusters were big enough to deserve their own prompt:

- `B6-multi-instance-content-library.md` — two VoLum instances or two processes
  clobbering one shared library. Highest deferred severity: it loses user
  content. Covers gpt56 `P4-6`, `P3-3`, opus5 `P-custom-content-library` 2, 7,
  `P-state-serialization-content` 3, 4, 9, 10, `P-neuralampmodeler` 7.
- `B7-audio-thread-rt-violations.md` — everything the audio thread does that it
  must not: allocate, free megabytes, construct/destroy models, call host and UI
  APIs, take blocking mutexes, run O(N²) bursts. Covers opus5 `P-audio-thread`
  2–6, 9, 12, 13, 15, `P-neuralampmodeler` 1, 2, 4, 12, gpt56 `P1-1`, `P1-2`,
  `P1-3`, `P9-1`, `P9-2`, `P9-3`, `P9-6`, `P9-7`, `P5-8`, `P8-3`, `P4-7`.
  Overlaps and supersedes parts of `P2-volum-1.2.0-rt-and-perf-hardening.md`.
- `B8-pdb-symbol-mismatch.md` — the shipped installer's binaries and the CI PDB
  artifact come from two different link steps, so symbols do not resolve for the
  build most users run. Debuggability only; no user-visible defect.

## Deferred, still only in the audit notes

Grouped by theme. Severity is as reported by the auditing pass.

### Deleting content that is currently playing

| Id | Sev | Title |
| --- | --- | --- |
| gpt56 `P6-3`, `P4-5`, opus5 `P-custom-content-library` 3 | MAJOR/BLOCKER | Deleting the active custom amp leaves its deleted capture playing behind factory UI, then overwrites the factory amp's scene |
| opus5 `P-overlay-manage-ui` 5 | MAJOR | Deleting a *non-focused* custom amp reverts the sidebar and hero to a factory amp while the custom amp keeps playing |
| opus5 `P-custom-content-library` 10 | MAJOR | Deleting a pedal loaded in a live PRE slot keeps it processing; factory scenes keep the dead index forever |

Why deferred: the fix is a content-removal transaction that has to reach the
audio graph, the sidebar, the hero and the per-amp scenes at once. That is the
same machinery the 1.2.1 cab-swap transaction touched, and re-opening it on
release night was the single riskiest thing available.

## Self-review of the fix batches (`audit-notes/selfreview/`)

Three Opus 5 agents re-audited the night's own diff rather than the shipped
1.2.1 code. Nineteen findings; sixteen were fixed in the two batches that
followed (`3905476`, `83d6a49`), including three that could lose user content
and two UI guards that did not actually guard anything. What is left:

| Id | Sev | Title | Why not now |
| --- | --- | --- | --- |
| `core-state` 2 | MEDIUM | `_VolumSyncUiFromState()` is not read-only: a lane whose resolved channel has no DIRECT capture has its restored IR id cleared, and the preset can come up `(unsaved)` right after a host preset switch | The repair itself is deliberate and predates tonight (`OnUIOpen` has done it since the 07/27 dead-reference fix); tonight only made the chunk path consistent with it. Splitting the applier into repair and display halves is a real change to restore semantics and wants its own pass. |
| `core-state` 7 | LOW | `OnUIClose` also fires when the standalone applies a Preferences change and when a VST3 host re-parents the editor, so those now switch the tuner off too | Correct-but-broad. Switching the tuner off is the safe direction; the alternative is a tuner that survives a device change. |
| `core-state` 8 | LOW | Clearing the SUPPORT amp is no longer silent on the next block: the lane keeps playing for one idle tick, or for the length of a model load if one is in flight | Behaviour change from the custom-SUPPORT fix, and a fade beats a hard cut. Belongs in the manual notes, not in a patch. |
| `library-host` 5 residuals | LOW | A watchdog kill during `WriteJsonAtomically` leaves a `*.tmp.<ticks>.<hash>` file that nothing reaps | Needs a reaper on startup; the watchdog is now scoped so tightly that reaching this is much less likely. |
| `library-host` 8 | MEDIUM | The buffer-size writeback persists the negotiated size only when the UI can represent it, so `settings.ini` still names the refused size in the case it cannot | The alternative is storing a size the panel cannot display. Wants a decision about whether the INI or the panel is authoritative. |
| `library-host` 9 | LOW | The ASIO input resolution in Preferences falls back to list position 0 when no input matches the output device, which the surrounding comments say cannot happen | Only reachable with an output-only ASIO driver. The fallback is wrong but harmless; the comment is the part that lies. |
| `ui-input` 8 | LOW | A rejected exact-value entry closes the box with no explanation, so a mistyped value looks like a broken box | Deliberate for 1.2.1 (cancelling beats moving the knob to zero). An inline "not a number" state is a design decision. |
| `ui-input` 6 nits | LOW | `ClampName(s, maxChars)` and `ShortCaptureLabel(name, maxChars)` compare bytes against a character budget, so a multi-byte name is cut shorter than the caller asked | Pre-existing, now merely conservative rather than corrupting. |

## Suggested order for 1.3.0

1. `B6` — multi-instance library. It is the only deferred cluster that destroys
   user content, and it gets worse as people build bigger libraries.
2. Deleting content that is currently playing (the three findings above). Same
   subsystem as `B6`; do them together or the transaction gets designed twice.
3. `opus5 P-custom-content-library` 1 + `P-state-serialization-content` 1 — the
   two one-shot IR calibration bugs, before more users import more IRs.
4. `gpt56 P2-9` — make the chunk reader forward-compatible *before* 1.3.0 writes
   chunks that 1.2.1 will misread.
5. `B7` — RT safety. Big, and the right time is alongside a deliberate
   performance pass, not squeezed next to feature work.
6. The UI polish table, which is cheap and highly visible.
7. `B8` — symbol mismatch, whenever the packaging scripts are next touched.
